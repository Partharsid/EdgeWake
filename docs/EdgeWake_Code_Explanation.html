🌲 EdgeWake: Complete Code Explanation

Welcome to the EdgeWake code explanation guide! This document breaks down exactly how the EdgeWake project works and provides a simple, line-by-line explanation of every single file in the code. This is perfect for understanding the project deeply for presentations or reports.

Part 1: How EdgeWake Works (The 5 Tiers)

EdgeWake is designed to save battery by remaining completely turned off until something happens. It does this using a 5-Tier Cascade:

Tier 1 (Deep Sleep): The ESP32-CAM shuts down its brain, WiFi, Camera, and Microphone. Only the physical pins listen for electricity. It uses almost zero power.
Tier 2 (Hardware Interrupt): When the Flame Sensor sees fire, or the Vibration Sensor feels a heavy impact, they send a jolt of electricity to a pin. This physically wakes the brain up.
Tier 3 (Edge AI Verification): Just because a sensor was bumped doesn't mean there is a fire. The brain turns on the Microphone and uses an Artificial Intelligence (TinyML) model to listen. If it doesn't hear a chainsaw or a fire, it goes back to sleep to save battery.
Tier 4 (Visual Capture): If the AI confirms the danger, the brain turns on the Camera, flashes the LED, and takes a photo as evidence.
Tier 5 (Cloud Handoff): Finally, the brain turns on the WiFi, logs into Telegram, sends the photo directly to your phone, and goes immediately back to Deep Sleep.

Part 2: Code Explanation (File-by-File)

1. Configuration (config.h)

This file acts as a dictionary. It defines the names of the WiFi, the passwords, and which pins connect to which sensors. Having it separate keeps the main code clean.

#define WIFI_SSID       "YOUR_WIFI_SSID"
#define TELEGRAM_BOT_TOKEN "YOUR_BOT_TOKEN"
#define TELEGRAM_CHAT_ID   "YOUR_CHAT_ID"
We define text strings (macros) for the credentials. Whenever the code says WIFI_SSID, it automatically replaces it with your actual WiFi name.
#define FLAME_SENSOR_PIN   GPIO_NUM_13
#define VIBRATION_SENSOR_PIN  GPIO_NUM_33
We assign the hardware sensors to specific physical pins on the board. GPIO 13 and 33 were chosen specifically because they are special "RTC Pins" that stay active during Deep Sleep.

2. The Main Logic (EdgeWake_Main.ino)

This file is the "director" that controls the 5 Tiers.

RTC_DATA_ATTR int bootCount = 0;
RTC_DATA_ATTR tells the ESP32 to store the bootCount variable in a special low-power memory chip (the RTC) that does not get erased when the device goes to Deep Sleep.
void setup() {
  esp_sleep_wakeup_cause_t wakeReason = esp_sleep_get_wakeup_cause();
  if (wakeReason != ESP_SLEEP_WAKEUP_EXT1) {
    goToDeepSleep();
    return;
  }
setup() runs the moment the device wakes up. We ask the board why it woke up using esp_sleep_get_wakeup_cause(). If it wasn't woken up by EXT1 (our external sensors), it was just a manual reboot, so we tell it to go right back to sleep.
  uint64_t wakeupPins = esp_sleep_get_ext1_wakeup_status();
  String alertType = "Unknown";

  if (wakeupPins & (1ULL << FLAME_SENSOR_PIN)) {
    alertType = "Fire";
  } else if (wakeupPins & (1ULL << VIBRATION_SENSOR_PIN)) {
    alertType = "Vibration";
  }
We ask the board exactly which pin jolted it awake. We use bitwise math (& and <<) to check if the binary 1 was on the Flame sensor pin or the Vibration sensor pin.
  if (initMicrophone()) {
    isRealThreat = verifyThreatAudio();
    deinitMicrophone();
  }
(Tier 3) We turn on the mic, run the verifyThreatAudio function (which asks the AI), and then immediately turn the mic off. If isRealThreat is false, we go to sleep.
  camera_fb_t *photo = NULL;
  if (initCamera()) {
    photo = capturePhoto();
  }
(Tier 4) If the AI confirms the threat, we initialize the camera and capture a photo. camera_fb_t is the memory type (Frame Buffer) that holds the image bytes.
  if (photo) {
    String message = "🚨 EDGEWAKE ALERT 🚨\nDanger Detected: " + alertType;
    sendAlertToTelegram(photo, message);
    esp_camera_fb_return(photo);
  }
(Tier 5) We build a text message string, send the photo to Telegram, and then use esp_camera_fb_return to safely empty the image from the memory chip so the board doesn't crash.
void goToDeepSleep() {
  uint64_t wakeMask = (1ULL << FLAME_SENSOR_PIN) | (1ULL << VIBRATION_SENSOR_PIN);
  esp_sleep_enable_ext1_wakeup(wakeMask, ESP_EXT1_WAKEUP_ANY_HIGH);
This tells the board to watch the Flame and Vibration pins while it sleeps. ESP_EXT1_WAKEUP_ANY_HIGH means "wake up if ANY of these pins receive electricity."
  rtc_gpio_isolate((gpio_num_t)I2S_SD_PIN);
  delay(5000);
  esp_deep_sleep_start();
}
We isolate the microphone pin so electricity doesn't leak out of it while sleeping. We delay(5000) to wait 5 seconds before sleeping, which gives the physical sensors time to calm down so they don't immediately wake the board up again. Then we put it to sleep!

3. The Artificial Intelligence (audio_utils.h)

const i2s_config_t i2s_config = {
  .mode                 = (i2s_mode_t)(I2S_MODE_MASTER | I2S_MODE_RX),
  .sample_rate          = 16000,
  .bits_per_sample      = I2S_BITS_PER_SAMPLE_16BIT,
This sets up the digital rules for the microphone. We listen at 16000 samples per second (16kHz), which is the exact speed the AI was trained to understand.
int total_samples = 32000;
int16_t *audioBuffer = (int16_t *)ps_malloc(total_samples * sizeof(int16_t));
16,000 samples per second * 2 seconds = 32,000 samples. We use ps_malloc to grab memory on the special extra memory chip (PSRAM) because standard RAM is too small.
  for (int i = 0; i < total_samples; i += 512) {
    i2s_read(I2S_PORT, &audioBuffer[i], 512 * sizeof(int16_t), &bytesRead, portMAX_DELAY);
  }
We rapidly pull tiny chunks of audio data (512 samples at a time) from the microphone via I2S and fill up our memory buffer until we have 2 seconds of audio.
  signal_t signal;
  numpy::signal_from_buffer(audioBuffer, total_samples, &signal);
  ei_impulse_result_t result = { 0 };
  run_classifier(&signal, &result, false);
We wrap the audio buffer into a "signal" that Edge Impulse understands, and then run run_classifier(), which feeds the audio through the Convolutional Neural Network (CNN) AI model.
    if (label == "fire") fireScore = score;
    if (label == "chainsaw") chainsawScore = score;
The AI gives us a score between 0.0 (0% sure) and 1.0 (100% sure) for every sound it knows. We grab the scores for fire and chainsaw. If they are over 0.60 (60%), it triggers the camera.

4. Camera Utilities (camera_utils.h)

  config.pixel_format = PIXFORMAT_JPEG;
  if (psramFound()) {
    config.frame_size   = FRAMESIZE_SVGA;
    config.jpeg_quality = 10;
We tell the camera to output a standard JPEG file. We check if the board has extra memory (psramFound()), and if so, we set the resolution to 800x600 (SVGA) with a high JPEG quality setting of 10.
  pinMode(FLASH_LED_PIN, OUTPUT);
  digitalWrite(FLASH_LED_PIN, HIGH);
  delay(150);
Before taking a picture, we turn on the bright white LED (Flash) and wait 150 milliseconds for the light to reach full brightness so the forest isn't dark.
  camera_fb_t *discard = esp_camera_fb_get();
  if (discard) esp_camera_fb_return(discard);

  camera_fb_t *fb = esp_camera_fb_get();
Crucial step: We take a photo and immediately throw it away (discard). We do this because the camera's auto-exposure algorithm takes a fraction of a second to adjust to the bright LED flash. The second photo (fb) will be perfectly exposed.

5. Telegram Upload (telegram.h)

  WiFiClientSecure client;
  client.setInsecure();
  client.connect("api.telegram.org", 443);
WiFiClientSecure allows us to talk to Telegram securely using HTTPS (port 443). setInsecure() skips checking complex SSL certificates, which keeps the code simple and saves memory.
  String boundary = "----EdgeWakeBoundary123456";
Because we are sending text AND a photo at the same time, we have to use an HTTP format called multipart/form-data. The "boundary" is just a text string that acts as a wall to separate the text from the image bytes.
  client.print(head);                  // Send text & headers
  client.write(fb->buf, fb->len);      // Send the actual image bytes
  client.print(tail);                  // Send the closing boundary
Crucial step: Instead of loading the entire request into RAM at once (which crashes the ESP32), we "stream" it. We send the text, then we push the raw image bytes directly from the camera buffer (fb->buf), and then we send the tail.
