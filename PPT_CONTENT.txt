=========================================
Title: The Problem — Why Forest Sensors Fail
Bullet Points:
• Forest fires destroy 10+ million hectares globally every year.
• Illegal logging and poaching go undetected in remote areas.
• Existing IoT sensors rely on fixed-schedule cloud communication.
• Constant Wi-Fi and sensor polling drains batteries in days, not months.
• Replacing batteries in dense forests is impractical and expensive.
• Result: Sensors die long before they detect a real threat.

SLIDE 3 — OUR SOLUTION
=========================================
Title: EdgeWake — The Solution
Subtitle: An ultra-low-power, multi-modal edge AI node that sleeps 99% of the time.
Key Idea:
• Instead of constantly polling the cloud, EdgeWake uses low-power analog tripwires (flame sensor, vibration sensor) to WAKE UP high-power systems (microphone, camera, Wi-Fi) ONLY when a real threat is detected.
• The device spends 99% of its life in deep sleep (~10 µA) and only uses full power (~160 mA) for 5 seconds during an actual alert.
• Battery life: months to years instead of days.

SLIDE 6 — TIER 1: DEEP SLEEP
=========================================
Title: Tier 1 — Deep Sleep (Near-Zero Power)
Content:
• The ESP32 CPU, Wi-Fi radio, and camera are physically powered OFF.
• Only the ULP (Ultra Low Power) co-processor remains active.
• Two analog sensors stay powered:
  - Flame Sensor (IR phototransistor) on GPIO 13
  - Vibration Sensor (SW-420) on GPIO 2
• Power draw breakdown (researched):
  - ESP32 chip alone in deep sleep: ~10 µA (Espressif datasheet)
  - ESP32-CAM board (unmodified): ~2.5 mA (onboard AMS1117 LDO and LED waste power)
  - Full sensor modules (with LM393 comparator): ~15 mA each
  - Solution: Use bare sensor switches (not module boards) → sleep current drops from 32.5 mA to ~2.55 mA
  - With LDO replaced (MCP1700, quiescent 1.6 µA) + LED removed: ~115 µA total
• Result: Battery life ranges from 5 weeks (easy build) to 2+ years (optimized build).
Visual: A dark, sleeping chip with two tiny glowing sensor dots.

=========================================
SLIDE 7 — TIER 2: HARDWARE INTERRUPT
=========================================
Title: Tier 2 — Hardware Interrupt (The Tripwire)
Content:
• An environmental anomaly occurs (fire, logging, landslide).
• The flame sensor detects infrared radiation OR the vibration sensor detects abnormal ground vibration.
• The sensor sends a HIGH voltage to an RTC GPIO pin.
• This triggers an ext1 hardware wake-up — the ESP32 powers on instantly.
• The firmware identifies WHICH sensor fired by reading the ext1 bitmask:
  - GPIO 13 HIGH → "Fire" alert
  - GPIO 2 HIGH → "Abnormal Vibration / Sound Detected" alert
• Debounce logic prevents repeated false triggers.
Visual: A lightning bolt hitting the chip, waking it up.

=========================================
SLIDE 8 — TIER 3: AUDIO VERIFICATION (EDGE AI)
=========================================
Title: Tier 3 — Edge Audio Verification
Content:
• Before activating the power-hungry camera, the system first verifies the threat using sound.
• The INMP441 I2S microphone records 2 seconds of audio at 16 kHz.
• Two analysis modes:
  1. Simple Mode: RMS energy threshold (works out of the box for demos).
  2. TinyML Mode: Edge Impulse model classifies sounds as "fire", "chainsaw", "background".
• If the audio confirms the threat → proceed to camera.
• If the audio says "false alarm" → go back to sleep immediately (saves massive power).
• This is the KEY power-saving innovation — most false alarms are caught here, BEFORE the camera and Wi-Fi are ever turned on.
Visual: A waveform/spectrogram graphic with a checkmark or X.

=========================================
SLIDE 9 — TIER 4: VISUAL CAPTURE
=========================================
Title: Tier 4 — Visual Evidence Capture
Content:
• Only reached if audio verification confirms a real threat.
• The OV2640 camera module powers on and captures a single high-resolution JPEG (800×600).
• Flash LED fires briefly for illumination in low-light forest conditions.
• Uses PSRAM for high-resolution frame buffers.
• The photo serves as court-admissible evidence for illegal logging or fire insurance claims.
Visual: A camera lens capturing a forest fire or chainsaw scene.

=========================================
SLIDE 10 — TIER 5: CLOUD HANDOFF
=========================================
Title: Tier 5 — Cloud Handoff & Instant Sleep
Content:
• The ESP32 briefly connects to Wi-Fi (typically < 3 seconds).
• Sends a multipart HTTP POST to an n8n webhook containing:
  - The JPEG evidence photo
  - Alert type ("Fire" or "Vibration")
  - Device ID and GPS/location
  - Audio RMS energy value
  - Timestamp
• After the server responds 200 OK, Wi-Fi is immediately turned off.
• The device returns to Tier 1 Deep Sleep within milliseconds.
• Total awake time: ~5 seconds. Then it sleeps again.
Visual: A cloud icon receiving data, then a "zzz" sleep icon.

=========================================
SLIDE 11 — CLOUD AUTOMATION (n8n WORKFLOW)
=========================================
Title: Cloud-Side Automation with n8n
Content:
• All heavy processing is offloaded to the cloud (the ESP32 must save power).
• n8n workflow handles:
  1. Webhook Trigger — receives the alert from the ESP32.
  2. Smart Router — routes by alert type (Fire / Vibration / Intruder / Unknown).
  3. Google Drive — stores the evidence photo with a timestamped filename.
  4. Telegram Bot — instantly pushes the photo + alert message to the user's phone.
• Fire alerts go to emergency channels.
• Vibration alerts go with message: "Possible illegal logging, landslide, or structural disturbance!"
• Fully automated — no human intervention needed from sensor trigger to phone notification.
Visual: A flowchart showing: Webhook → Router → [Google Drive + Telegram].
